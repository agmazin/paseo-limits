# Проверка 0.2.10

Причина: файловый снимок возвращался без учёта настроек провайдеров. В macOS обработчик refresh также обходил общий путь чтения.

В SDK 0.12.0 `providers.listAvailable()` возвращает `{providers:[{provider,available,error}]}`. Признака enabled в этом ответе нет. `config.get()` возвращает `{requestId,config:{providers:{[id]:{enabled?}}}}`. Фильтрация использует только явный `enabled:false`, без проверки status или available. Конфигурация запрашивается после получения исходного снимка на каждом read/refresh, вне минутного кеша usage. При ошибке конфигурации сохраняется последняя известная видимость. Исходные данные и fetchedAt не изменяются.

`limits.read` и `limits.refresh` проходят через один фильтр для файла поллера, `PASEO_LIMITS_FILE` и `PASEO_LIMITS_SOURCE=paseo`. Клиентское событие каталога провайдеров вызывает чтение свежей конфигурации. Inline, pill и поповер используют общее состояние. При отсутствии видимых окон inline не занимает места, pill скрыта.
